# 水果切切乐开发设计

## 1. 项目目标

本项目是一款面向电脑浏览器的前后端分离小游戏。玩家注册并登录后，使用鼠标移动形成刀光，不需要按住鼠标。刀光碰到水果时完成切割并计分，漏掉水果或切中炸弹会扣除血量。

第一版包含 5 个按顺序解锁的闯关关卡。通关第 5 关后解锁无尽模式，无尽模式成绩进入全服排行榜。手机版触控和 Vue 3 升级属于后续版本。

项目同时承担学习目标：每次只增加约 50-100 行核心代码，学习者运行、理解并完成小练习后，再进入下一阶段。

## 2. 第一版范围

### 2.1 包含

- 用户注册、登录和退出
- 登录状态保持
- 关卡选择与顺序解锁
- 5 个限时目标分数关卡
- 鼠标移动切水果，无需按键
- 不同水果分值和连切奖励
- 100 点血量、漏水果扣血、炸弹扣血
- 通关进度自动保存
- 通关第 5 关后解锁无尽模式
- 无尽模式个人最高分和全服排行榜
- 基础音效开关与游戏暂停
- 桌面端响应式布局

### 2.2 暂不包含

- 手机触屏操作
- Vue 3
- 第三方登录、好友、聊天和支付
- 多人实时对战
- 道具、皮肤、每日任务和成就系统
- 管理后台

## 3. 技术方案

### 3.1 前端

- HTML5：页面语义结构和 Canvas 元素
- CSS3：布局、响应式尺寸、动画和视觉状态
- Vue 2.7：页面、组件和界面状态
- Vite：开发服务器和构建工具
- Vue Router：登录、关卡、游戏和排行榜页面路由
- Axios：调用后端 JSON API
- Canvas 2D：水果、炸弹、刀光、粒子和切开动画
- 原生 JavaScript 模块：游戏循环、生成器、碰撞和计分规则

Canvas 游戏引擎与 Vue 页面分离。Vue 只负责开始、暂停、结算和界面显示；高频动画由 `requestAnimationFrame` 驱动，避免每帧触发 Vue 响应式更新。后续迁移 Vue 3 时，游戏引擎可以原样保留。

Vue 单文件组件会同时练习三部分：`template` 编写 HTML 结构，`script` 编写 Vue 与 JavaScript 逻辑，`style` 编写组件 CSS。全局样式、页面布局和 Canvas 外围 HUD 会放在独立 CSS 文件中，不使用组件库代替基础 HTML/CSS 学习。

### 3.2 后端

- Java 21 LTS
- Spring Boot 3
- Spring Web：REST API
- Spring Security：身份认证和访问控制
- 服务端 Session：通过 HttpOnly Cookie 保存登录状态
- BCrypt：密码哈希
- MyBatis：数据访问和显式 SQL
- MySQL 8
- Maven：依赖与构建

开发环境通过 Vite 代理 `/api` 到 Spring Boot，生产环境通过反向代理让前后端保持同源。这样可以使用安全的 HttpOnly Session Cookie，并减少跨域配置。

### 3.3 工程结构

```text
Fruit-party/
├─ fruit-party-web/       Vue 2 前端
├─ fruit-party-server/    Spring Boot 后端
├─ docs/                  设计与学习文档
└─ README.md              启动方式和项目说明
```

## 4. 页面与模块

### 4.1 页面

- 注册页：创建账号并显示字段校验结果
- 登录页：登录后进入游戏大厅
- 游戏大厅：显示用户、最高进度和模式入口
- 关卡选择页：显示 5 关以及锁定、可玩、已通关状态
- 游戏页：Canvas、分数、目标、剩余时间、血条、暂停按钮
- 结算页：显示成功或失败、得分、连切统计和下一步操作
- 排行榜页：显示无尽模式前 20 名及当前用户最佳成绩

### 4.2 前端边界

- `views`：组织完整页面
- `components`：血条、计时器、弹窗等可复用界面
- `game`：与 Vue 无关的游戏核心代码
- `api`：封装后端请求
- `router`：路由和登录访问控制
- `store`：仅保存用户和全局设置，不保存逐帧游戏对象

### 4.3 后端边界

- `auth`：注册、登录、退出和当前用户
- `level`：关卡配置、进度查询和通关记录
- `game`：游戏场次创建、结算和合理性校验
- `ranking`：个人最佳成绩和全服排行榜
- `common`：统一响应、异常处理和公共配置

## 5. 游戏规则

### 5.1 操作

- 点击“开始游戏”后进入 3 秒倒计时。
- 倒计时结束后监听 Canvas 内的鼠标移动。
- 相邻两个鼠标坐标构成一条切割线段。
- 线段与水果碰撞圆相交时，水果只被计算一次。
- 鼠标离开 Canvas 时清空轨迹，防止重新进入时产生跨屏切割。
- 暂停、页面失焦或游戏结束时停止生成和碰撞检测。

### 5.2 分值

| 类型 | 基础分值 |
|---|---:|
| 苹果 | 10 |
| 橙子 | 15 |
| 西瓜 | 20 |
| 金色水果 | 50 |

250 毫秒内连续切中多个水果构成一次连切。基础分先分别累加，再按本次连切数量增加奖励：2 个奖励 10 分，3 个奖励 30 分，4 个及以上奖励 60 分。切中炸弹会立即中断连切。

### 5.3 血量与失败

- 每局初始血量为 100。
- 普通水果落出画面底部时扣 10 点血。
- 切中炸弹时扣 30 点血。
- 血量最低为 0，不出现负数。
- 血量归零立即失败。
- 时间结束且未达到目标分数时失败。
- 达到目标分数时立即通关，不必等待倒计时结束。

### 5.4 五关配置

| 关卡 | 时限 | 目标分数 | 基础生成间隔 | 速度倍率 | 炸弹概率 | 设计目的 |
|---|---:|---:|---:|---:|---:|---|
| 1 | 60 秒 | 300 | 1000 ms | 1.00 | 0% | 熟悉移动切割和漏果扣血 |
| 2 | 60 秒 | 500 | 850 ms | 1.10 | 5% | 引入炸弹 |
| 3 | 60 秒 | 750 | 700 ms | 1.20 | 8% | 练习连切与目标选择 |
| 4 | 75 秒 | 1100 | 600 ms | 1.35 | 12% | 提高密度和持续操作压力 |
| 5 | 90 秒 | 1600 | 500 ms | 1.50 | 15% | 综合挑战并解锁无尽模式 |

生成间隔允许在基础值上下随机浮动 15%，避免机械节奏。每一关必须在上一关通关后解锁，已经通关的关卡可以重复游玩。

### 5.5 无尽模式

- 通关第 5 关后解锁。
- 不设时间上限和目标分数，血量归零后结束。
- 初始规则接近第 2 关。
- 每经过 30 秒提高一级难度，逐步缩短生成间隔并提高速度与炸弹概率。
- 生成间隔最低为 300 ms，速度倍率最高为 2.20，炸弹概率最高为 20%。
- 仅无尽模式最高分进入全服排行榜。

## 6. 数据模型

### 6.1 用户 `users`

- `id`：主键
- `username`：唯一用户名，4-20 个字符
- `password_hash`：BCrypt 密码哈希
- `created_at`：注册时间
- `updated_at`：更新时间

密码长度为 8-64 个字符。接口永远不返回密码哈希。

### 6.2 玩家进度 `player_progress`

- `user_id`：用户主键，一名用户只有一条进度
- `highest_level`：当前已解锁的最高关卡，初始为 1
- `endless_unlocked`：无尽模式是否解锁
- `updated_at`：更新时间

### 6.3 游戏场次 `game_sessions`

- `id`：场次主键
- `user_id`：所属用户
- `mode`：`LEVEL` 或 `ENDLESS`
- `level_number`：闯关关卡，无尽模式为空
- `started_at`、`finished_at`：开始与结束时间
- `score`：最终得分
- `remaining_health`：剩余血量
- `result`：`PLAYING`、`WIN`、`LOSE` 或 `ABANDONED`

场次由后端创建。结算时后端根据模式、持续时间、得分上限和场次状态做基础合理性校验，降低直接伪造排行榜成绩的风险。第一版不承诺抵御专业作弊工具。

## 7. 主要接口

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/auth/register` | 注册 |
| POST | `/api/auth/login` | 登录 |
| POST | `/api/auth/logout` | 退出 |
| GET | `/api/auth/me` | 获取当前用户 |
| GET | `/api/progress` | 获取关卡进度 |
| POST | `/api/games` | 创建游戏场次 |
| POST | `/api/games/{id}/finish` | 提交本局结算 |
| GET | `/api/rankings/endless` | 获取无尽模式前 20 名 |
| GET | `/api/rankings/endless/me` | 获取个人最高分与名次 |

所有写接口执行服务端字段校验。未登录访问游戏、进度和排行榜个人接口时返回 HTTP 401；越权、重复结算或游玩未解锁模式时返回 HTTP 403 或 409；统一异常响应包含稳定错误码和可显示的中文消息。

## 8. 数据流

1. 用户登录，浏览器通过 HttpOnly Cookie 保持 Session。
2. 大厅读取玩家进度，决定关卡与无尽模式是否可点击。
3. 玩家选择模式，前端请求后端创建一条游戏场次。
4. 后端校验解锁状态并返回场次编号与关卡配置。
5. 前端运行本地 Canvas 游戏，不发送逐帧数据。
6. 游戏结束后，前端提交场次编号和统计结果。
7. 后端完成合理性校验，在同一事务中保存成绩并更新进度。
8. 前端显示结算结果，必要时刷新关卡或排行榜。

网络断开不会中止正在进行的本地画面。结算提交失败时保留本局结果并允许重试；同一场次只能成功结算一次，防止重复加分或重复解锁。

## 9. 视觉与交互

- 使用清爽卡通街机风，背景、普通水果、稀有水果、危险物之间有明显色彩区分。
- 游戏画布使用稳定的 16:9 比例，并按容器缩放坐标。
- HUD 固定显示分数、关卡目标、剩余时间和血条，不随数字变化跳动。
- 刀光在约 120 毫秒内逐渐消失，不无限保留轨迹。
- 水果被切后短暂显示两半和果汁粒子，随后回收对象。
- 炸弹有独立轮廓、警示色和音效，不能只靠颜色区分。
- 暂停按钮使用图标并提供提示；浏览器失焦时自动暂停。
- 设置中可以关闭音乐和音效，设置保存到浏览器本地。

## 10. 测试与验收

### 10.1 前端

- 纯 JavaScript 单元测试：线段与圆碰撞、计分、连切、扣血和关卡完成条件
- Vue 组件测试：血条、倒计时、关卡锁定和结算状态
- 浏览器流程测试：注册、登录、第一关、进度保存和排行榜
- 人工检查：不同桌面尺寸下无文字遮挡、Canvas 非空、暂停和失焦行为正确

### 10.2 后端

- JUnit：业务规则和分数合理性校验
- MockMvc：注册、登录、权限、场次创建和结算接口
- 数据库集成测试：唯一用户名、重复结算和并发更新最高分
- 安全检查：密码不明文保存、Cookie 为 HttpOnly、受保护接口不能匿名调用

### 10.3 第一版完成标准

- 新用户可以完成注册、登录和退出。
- 玩家只能按顺序解锁 5 个关卡。
- 鼠标无需按键即可稳定切中水果。
- 分数、连切、时间、血量和炸弹规则符合本文档。
- 刷新或重新登录后通关进度仍然存在。
- 第 5 关通关前无法进入无尽模式，通关后可以进入。
- 无尽模式最高分可以可靠保存并显示在排行榜中。
- 前后端测试通过，生产构建成功。

## 11. 教学式开发节奏

每个学习单元遵循同一流程：说明本次目标与前置知识，新增约 50-100 行核心代码，逐段解释，运行验证，布置一个小修改，学习者确认掌握后继续。依赖清单、生成文件和重复样板不计入核心代码行数，但仍会解释用途。

建议顺序如下：

1. 初始化 Git、Vue 2 和 Vite，认识前端目录与启动命令。
2. 创建第一个页面和路由，理解单文件组件。
3. 初始化 Spring Boot，认识 Maven 与分层结构。
4. 编写健康检查接口，让 Vue 成功访问后端。
5. 配置 MySQL 和数据库迁移。
6. 完成注册的数据库、后端接口和前端表单。
7. 完成登录、Session、退出和路由保护。
8. 搭建游戏页与稳定比例的 Canvas。
9. 完成游戏循环和鼠标刀光。
10. 完成一个水果的运动和对象生命周期。
11. 完成线段碰撞与切中效果。
12. 完成计分、连切、血量和炸弹。
13. 完成第一关的开始、暂停、成功和失败闭环。
14. 把关卡数值配置化并加入其余四关。
15. 保存通关进度并实现关卡锁定。
16. 实现无尽模式、难度增长和最高分。
17. 实现排行榜、错误恢复和基础防作弊校验。
18. 添加素材、音效、测试、生产构建与部署配置。
19. 在功能稳定后，将 Vue 2 分阶段迁移到 Vue 3。

实现过程中允许根据测试结果微调关卡数值，但不得静默改变核心规则；数值修改需要同步更新本文档。

### 11.1 每天 4 小时的学习方式

每天建议完成 2 个小学习单元，每个单元新增 50-100 行核心代码。4 小时按以下方式分配：

- 30 分钟：复习上一天内容，口述数据流和关键代码
- 75 分钟：学习并实现第一个增量
- 75 分钟：学习并实现第二个增量
- 45 分钟：运行测试、排错和浏览器检查
- 15 分钟：记录当天结论与第二天问题

学习者必须能解释本次新增代码、独立运行验证，并完成一个小修改，才把该单元标记为掌握。没有掌握时顺延计划，不通过一次性增加代码量追赶进度。

### 11.2 两周参考进度

完整第一版预估需要 48 小时，可放在 14 个自然日内完成，其中约 12 天用于开发，2 天作为休息或排错缓冲。下表表示推荐的学习顺序和工作量，不是必须严格遵守的日历。当天达到学习验收标准后，可以直接提前开始下一阶段；遇到尚未掌握的内容则顺延，不用为了赶日期跳过理解与测试。

| 开发日 | 主要成果 | 当天重点 |
|---|---|---|
| 第 1 天 | Git、Vue 2、Vite、首页 | 工程目录、HTML 模板、基础 CSS、启动命令 |
| 第 2 天 | 路由与游戏大厅静态界面 | Vue 组件、Props、Flex/Grid、页面导航 |
| 第 3 天 | Spring Boot 与健康检查 | Maven、Controller、JSON、前后端代理 |
| 第 4 天 | MySQL 表与 MyBatis | 建表、实体、Mapper、数据库连接 |
| 第 5 天 | 注册与登录后端 | 参数校验、BCrypt、Session、异常响应 |
| 第 6 天 | 注册与登录前端 | 表单、Axios、登录状态、路由保护 |
| 第 7 天 | Canvas 单机 MVP | 游戏循环、鼠标刀光、一个水果、碰撞；达到可玩里程碑 |
| 第 8 天 | 完整基础规则 | 多种水果、炸弹、分值、连切、血条、倒计时 |
| 第 9 天 | 第一关闭环与结算 | 开始、暂停、成功、失败、结算界面 |
| 第 10 天 | 五关与进度保存 | 配置化关卡、顺序解锁、事务更新 |
| 第 11 天 | 无尽模式与排行榜 | 动态难度、最高分、前 20 名、基础校验 |
| 第 12 天 | 素材、测试与上线准备 | 音效、错误恢复、自动测试、生产构建、部署文档 |

第 7 个阶段结束时应得到“可登录、可游玩的第一关 MVP”，第 12 个阶段结束时得到完整联网第一版。进度快时可以在同一天完成多个阶段；进度慢时可以用多天完成一个阶段。无尽模式、排行榜、完整测试和上线准备不能为了追赶日期而省略。
